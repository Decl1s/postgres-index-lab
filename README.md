Я сравниваю одинаковые строки SELECT до и после индекса и объясняю план без обещаний фиксированного ускорения.

**Я сначала проверяю, что SQL возвращает те же строки, затем измеряю эффект индекса.**

Я сделал учебный эксперимент для задачи магазина: получить последние оплаченные
заказы одного продавца за период. На одинаковых синтетических данных я сравниваю
один SELECT до и после частичного покрывающего B-tree индекса.

**PostgreSQL 16 · SQL · EXPLAIN ANALYZE BUFFERS · Python 3.12**

## Что я показываю за 5–10 минут

1. Я создаю собственный временный PostgreSQL без TCP и загружаю 60004 заказа.
2. Я сохраняю результат SELECT и пять JSON EXPLAIN после отдельного прогрева.
3. Я создаю индекс по продавцу и времени для `status='paid'`, добавляю `amount_minor` через INCLUDE.
4. Я повторяю тот же SELECT и сравниваю весь упорядоченный результат, а не только count.
5. Я сохраняю планы, все замеры, размер индекса и читаемый отчёт; свой кластер останавливаю и удаляю.

В первом локальном опыте я получил `Limit → Sort → Seq Scan` до индекса и
`Limit → Index Only Scan` после него. Медиана execution time изменилась
с **5.194 до 0.047 ms**, shared hit первого измерения — с **1771 до 5**.
Это наблюдение одного прогретого локального опыта, не гарантия ускорения на другой БД.
Я не выключаю seq scan и не задаю фиксированную планку скорости в тестах.

## Как я запускаю эксперимент

Мой полный профиль — **Linux x86_64**, обычная учётная запись, Python 3.12 и
уже установленные `postgres`, `initdb`, `pg_ctl`, `psql` одной версии 16.x.
Локально я проверил **16.15**. Я не устанавливаю системный сервер и не запускаю
существующий кластер. Python-пакетов из PyPI проекту не требуется.

```bash
python3.12 -m venv .venv
.venv/bin/python -m index_lab demo --pg-bin /usr/lib/postgresql/16/bin --output workspace/demo
.venv/bin/python -m index_lab verify workspace/demo
```

Я открываю `workspace/demo/REPORT.md`. В каталоге также лежат `summary.json`,
`result.json`, `before.plans.json`, `after.plans.json`, `manifest.json`.
Успешный verify печатает `{"verified": true}`. Повтор с тем же `--output`
даёт отказ с exit=2 и сохраняет прежние файлы. Для нового опыта я выбираю новое имя.

| Аргумент | Что я меняю | Граница |
| --- | --- | --- |
| `--rows` | Я задаю число обычных синтетических заказов; ещё четыре добавляю для границ времени | 1000–200000, по умолчанию 60000 |
| `--merchant` | Я выбираю продавца | 1–100, по умолчанию 42 |
| `--limit` | Я ограничиваю число возвращённых строк | 1–1000, по умолчанию 50 |
| `--runs` | Я задаю число измерений каждой фазы, без warm-up | 1–9, по умолчанию 5 |
| `--pg-bin` | Я явно выбираю уже установленный набор PostgreSQL 16 binaries | Каталог с четырьмя программами |
| `--output` | Я выбираю новый каталог bundle | Существующий результат не перезаписываю |

Если PostgreSQL 16 отсутствует, я могу выполнить быстрые unit-тесты без него.
Полную лабораторию на Windows/macOS я в 0.1.1 не поддерживаю: использую Linux
и приватные Unix-сокеты. В Windows CI я отдельно проверяю unit и упаковку.

## Как я проверяю проект

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m unittest discover -s tests -p integration.py -v
.venv/bin/python scripts/smoke.py
.venv/bin/python scripts/zip_smoke.py --postgres
```

Я ожидаю **21 unit + 6 integration**. Integration создаёт только свои одноразовые
кластеры. Для нестандартного пути в integration/smoke я задаю `INDEX_LAB_PG_BIN`;
DSN, адрес и пароль чужой БД приложение не принимает.

Я проверяю равенство строк, границы периода, детерминированную сортировку,
метрики, отказ SQL, изоляцию PG-переменных, остановку после исключения,
повреждение отчёта, отказ перезаписи, публикацию после сбоя и запуск из ZIP.
Я не проверяю «обязательное ускорение в N раз»: время зависит от условий опыта.

## Где я продолжаю обучение

Я начинаю с [query.sql](index_lab/sql/query.sql) и [index.sql](index_lab/sql/index.sql),
затем разбираю [core.py](index_lab/core.py). В [NOTES](NOTES.md) я объясняю
селективность, порядок ключей, INCLUDE, visibility map и ошибки чтения buffers.
Там же я оставил пять упражнений с проверяемыми ответами.

Я храню только синтетические данные и не подключаюсь к рабочей БД. Результаты,
базы, пароли, окружения и локальные пути в публичный архив не включаю.
